# ВЕКРА — сервис обработки заявок

Рабочий MVP для одной команды: русскоязычный лендинг, интерактивное публичное демо, форма заявки с реальным сохранением в SQLite, закрытый кабинет `/admin`, поиск, фильтры, заметки, статусы, удаление и персонализированные черновики писем. Сервер валидирует данные, доступ защищён сессией в HttpOnly cookie, мутации — проверкой Origin, попытки входа и заявки ограничены по IP.

## Быстрый запуск без зависимостей

Нужен Python 3.12+. Из корня проекта:

```bash
export ADMIN_PASSWORD='задайте-свой-длинный-случайный-пароль'
export PUBLIC_URL='http://localhost:8000'
python server.py
```

Откройте http://localhost:8000, отправьте заявку и войдите в http://localhost:8000/admin с заданным паролем. Данные сохраняются в `data/vektra.sqlite3`, в том числе после перезапуска. Пароль не записывается в базу; храните его в секретах окружения, не в Git. Минимум 16 символов. Сессии действуют 8 часов. Для отзыва всех сессий остановите сервис и очистите таблицу `sessions` перед сменой пароля.

## Docker / production

```bash
cp .env.example .env
# Заполните ADMIN_PASSWORD и PUBLIC_URL в .env
# Для внешнего домена: PUBLIC_URL=https://ваш-домен
# Запустите:
docker compose up --build -d
```

Контейнер запускается через Gunicorn, данные в именованном томе `vektra-data`. Для публикации нужен сервер с Docker, домен и reverse proxy (например Caddy/Nginx) с HTTPS на порт 127.0.0.1:8000. `PUBLIC_URL` должен точно совпадать с origin в браузере (протокол, хост и порт, без пути). Для HTTPS автоматически включается Secure cookie. GitHub Pages не запускает Python: там будет доступен лишь интерфейс без API. Веб-сервис должен обслуживать и HTML, и API с одного origin. HTTPS и постоянный том обязательны для рабочего размещения. Один экземпляр приложения, локальный диск SQLite. Не предназначено для serverless с эфемерным диском.

За reverse proxy все запросы могут иметь один IP: базовые лимиты тогда общие. Для публичной нагрузки настройте лимиты на proxy с корректной доверенной цепочкой IP. Приложение намеренно не доверяет произвольному X-Forwarded-For.

## Что реализовано и где границы

- Публичное демо из трёх вымышленных компаний отделено от настоящих заявок.
- Приоритет реальных лидов: база 20 баллов + компания 15 + сайт 15 + контакт 10 + Professional/Enterprise 20 + стадия «Встреча» 20. Это правила, а не AI и не вероятность сделки.
- Письмо собирается сервером из реальных полей заявки. Внешняя AI-модель и отправка email не подключены; ключи не нужны. Текст можно править, сохранять и копировать.
- Кабинет показывает до 1000 последних лидов; поиск, статистика и фильтры работают по этой выборке. Это MVP одной команды с общим паролем, без отдельных аккаунтов, ролей и мультитенантности.
- Цены и пакеты перенесены из исходной демо-страницы; их условия обсуждаются отдельно, биллинга нет. Перечень услуг в тарифах не означает наличие соответствующих интеграций в этом MVP.
- После сохранения заявка доступна команде в кабинете. Автоматические email/Telegram-уведомления и гарантированный срок ответа не заявляются.
- Согласие и его время сохраняются. До публичного приёма персональных данных владелец должен указать реквизиты оператора, контакты и свою политику обработки данных. Не храните секреты в заметках.

## Проверка

```bash
python -m unittest -v
node --check app.js
node --check admin.js
node test_frontend.cjs
```

HTTP-тесты проходят через WSGI: сохранение и чтение после повторного подключения к БД, запрет анонимного доступа, вход/выход, статусы, заметки, черновики, удаление, валидация, Origin, лимиты, статика и запрет доступа к серверным файлам.

`GET /health` проверяет доступ к базе. Бэкап делайте SQLite backup API (не копированием открытого файла без WAL); регулярно проверяйте восстановление. Для резервной копии можно выполнить:

```bash
python -c "import sqlite3; s=sqlite3.connect('data/vektra.sqlite3'); d=sqlite3.connect('backup.sqlite3'); s.backup(d); d.close(); s.close()"
```

Файл бэкапа содержит персональные данные, храните его вне публичной директории. В Docker путь базы `/data/vektra.sqlite3`. Статический обработчик отдаёт только явно разрешённые frontend-файлы.
